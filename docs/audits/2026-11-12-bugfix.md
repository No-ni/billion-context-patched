## 上次报告与实际修复

管理器不运行 install.mjs 的根因成立，但此前修复还调用了不存在的 suppress()，导致三个子插件都没挂载。仅靠 entry-init guard 也没有覆盖实际 Loader 的初始并发 import。现在先等待原版初始化与 dispose，再挂 children；作用域清理由 Cordis effect 完成。

管理器首次启用自行迁移 profile，在 HMR 独占队列中使用官方文件锁及原子写入，并协调重载；重载失败保留待处理状态并重试。旧加速器配置、分行状态和缺失字段迁移到包装包，已有包装包值优先；YAML 别名、合并键、标签、注释及无关配置保留。自定义条件行保留，旧包装包跟随行才清理。

两指定主机逐字段补 enabled=true 与 encoding=auto，按真实 LLM 目录和原始配置判断缺失，等待迟到服务与渠道；schema 生成的 false 不当作用户选择。显式渠道 false/gzip/null/表达式和全局 gzip 保留，冲突时重读最新 revision。

全量检查还发现 Windows 图片 JPEG 保存失败、把系统 convert 当作 ImageMagick、修改 maxDim 后返回旧缓存三个问题。现已修复，检查不能再把存在后端但编码失败记为 skip；installer 候选检查也加入图像折叠/编码。

收尾检查确认旧加速器的异步账本打开未被 Cordis 跟踪，禁用时可能提前清理并泄漏后打开的域。现在同步取消尚未执行的原版 fiber；已经运行且在打开账本的原版先完成 Promise 链，再由它自己关闭。内置账本使用可迟到的 storage/storageDomain 作用域，关闭等待打开完成、先冲刷队列、始终释放自己取得的 handle，读失败与表解析失败也不泄漏。共享设施里外部 owner 的账本不会被包装层关闭。

最终组合层按原版 entry 是否已有活跃 fiber 区分冷启动与热安装：前者提前禁用，后者由包装层等旧账本完成后禁用。账本回归直接执行最终组合层表达式，验证它不会在热安装时提前销毁原版、绕过账本等待。

check-runtime 使用从实际 DSH NEXT app.asar 读取的 Loader、Cordis、Schemastery、SettingsForms、atomic-write。模型插件、LLM 目录、configEditor 持久化与 HMR 为脚本开头列明的替身；HMR 替身检查独占/禁止嵌套，并主动注入一次失败验证重试。因此该检查不等于真实 DSH 完整安装。

check-ledger-runtime 另用实际 Cordis、Loader、Storage、DomainFacility、内置 accelerator 和自带 Zod；存储介质、连接路由、模型迭代器为隔离替身。原版部分直接执行被替换的精确账本片段；不把该片段测试称为整个原版插件集成。无真实模型调用、代理启动或用户 profile 读写。

本轮收尾重新运行完整 build、wrapper、runtime、ledger-runtime 和 restart 检查，并核对提取的 532 个宿主运行文件与当前安装的 DSH NEXT app.asar 完全一致。旧片段与起点一致，迁移及重复补丁仍与最终产物逐字节相同。
