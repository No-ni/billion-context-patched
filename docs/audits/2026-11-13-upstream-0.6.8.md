# 0.6.8 上游吸收与兼容核对

本次按用户批准的整体推荐方案吸收固定上游，授权范围包括子代理、隔离模拟端到端测试、独立 bug 扫描、修复复测、向自己的 origin 提交推送，以及从 0.6.7 发布为 0.6.8。没有安装、重启真实插件或改动用户 profile、配置、日志、会话数据库。

## 来源与范围

- 本仓库：`No-ni/billion-context-patched`，原基线 `cf5f5fec14d4198e76e78e84998e119d951973e7`；在 `update/upstream-0.6.8` 功能分支准备。
- bili：从 `406193b202c13248241f25201e1c6bbda747c99b` 更新至 [固定提交 0d94a8a2](https://github.com/ranxianglei/billion-context/commit/0d94a8a240fa0f7648f84032b03150f6b1891167)，包版本仍为 0.1.213，kernel 0.0.189 → 0.0.196。未继续追踪之后的 master。
- accelerator：保留 2.3.0 / `e8c30af1f2b5cffa6749d032f0f296e17d4e26d0`，既有账本生命周期及 YAML/Zod 寻址补丁保留。
- 固定 bili 源码在独立目录以 Node v24.18.0、npm 11.16.0 执行 `npm ci`（618 个依赖）和 `npm run build`。只复制 installer 规定的七个文件；`build-info.json` 为 `{"commit":"0d94a8a"}`。
- service/native/client 只通过三个补丁器生成；没有手改 minified vendor。外部 bili 输入先打 service/native 补丁，installer 在临时副本检查后才替换正式产物，合并客户端时施加 client 补丁。

## 修复和独立扫描

1. 快照一次实际读失败会让 raw fallback 先进入 kernel 的实例编号/同步节点，停用仍有效的块，B22 因而不再有 active 块可恢复。改为只对当前已证明的暂时 miss 暂缓该次内核及后置归档/孤儿清理；快照、同步索引、保存排队照常，保留所有正常编辑/rebase 与拒绝条件。
2. fork 预留引用首次盖子时间后，下一轮裸消息被父高水位挡住。仅为已证明首次显示的 child stamp 记录有界可见性集合；普通旧史和 disabled/模糊历史不获豁免，副本、克隆与持久化同步。
3. 全部 native WS factory 的 mixed-case object/重复 tuple/Headers 原来会混入旧宿主标记。通过 Headers 的 case-insensitive set 唯一替换权威 stamp，保持 init/protocol/container 形状和未知类型透传。
4. 图片回执原来按 session pending 共享，并且辅助发送有遗漏。改为请求独立的 opaque 回执，只 credit 最终发送的明文图片；initial/retry/loop/JSON continuation 的变换、重签、头投影、压缩和成功入口共同适配。
5. 独立只读扫描复现 full/jsonWriter=off 的 scheduleSave 微任务先把重做 requests=2 落盘，finally 只改内存为1。修复复位后重新排队保存，并覆盖 success/fail-fast/throw/disconnect；重做期间断开也取消后续转发。
6. 实际 receive/decode/ingest catch 和辅助请求 side window guard 仍把原英文放在 message。统一中文短句，原文放 detail，保留真实 reader/codec/分类/分词/guard、413/type/stage/code/retryable。完整读后的 decode/ingest 及 side 拒绝已由真实 localhost HTTP 验证；receive reader 会 destroy 请求，不能承诺其分支 JSON 在 socket reset 前必定送达。
7. 小 WS 续接帧可在完整历史重建后超限；完整 session/history 的本地 errorFrame 原来仍报英文。仅本地 413/5xx 中文化并保留 detail；实际帧 1257 B 小于 cap 1536 B，展开后拒绝，checkpoint 未污染，同一 checkpoint 健康续接成功，拒绝期间 gateway 发送为0。完整 upstream 的握手失败后 HTTP prewarm 不完整/fetch 失败也复验通过；generate=false prewarm 是连接预热，不冒充模型轮。
8. 模型隧道 pre-DNS 的 unresolvable 502 原来暴露英文长诊断。中文可见错误保留 code=tunnel_destination_denied、detail=unresolvable，完整原文进入 upstreamFailure.hint，kind=dns/host 保留。独立实际主线程三次 DNS 及新 worker 复现 ENOTFOUND，修复后复验通过，worker exit0；格式/策略 400/403 保持。

最终冻结 service `ea9406a4…` 上五个独立 probe（落盘计数、ingress、side、WS 和 DNS）全部通过。系统扫描覆盖本地模型 HTTP/JSON/流/WS 413/502 出口；增量存储不可用 503 保留内部 ack/重新探测契约，管理/启动界面和原始 CONNECT/upgrade 状态行另有语义，真实上游状态转发不被替换。

落盘保证依赖存储写入成功。独立 probe 故意令纠正保存构建失败时，原 prepare 异常仍保持、错误有日志、pending 与监听被释放；不能把故意失败的存储写入算作持久计数保证。最终独立审查已完成实际四协议 deferred kernel/archive/orphan/rewrite/诊断调用点、fork stamping/clone/hydration/存储白名单、源差异及生成物核查，全部通过，未发现尚未解决的生产缺陷。

## 交付与边界

功能提交先记录以上方案与本地证据；干净树执行 `node scripts/release.mjs 0.6.8`，版本准备单独中文提交。推送功能分支并等待 Ubuntu Node22/24、Windows/macOS Node24 全部检查成功；fresh fetch 后 main 快进至该提交，annotated `v0.6.8` 和 main 原子推送。`release.yml` 是唯一发布者，最终核对公开中文 Release、ZIP、SHA256SUMS 和远端标签解引用。

发布执行结果以该标签的 GitHub Actions 和 [Release](https://github.com/No-ni/billion-context-patched/releases/tag/v0.6.8) 实时记录为准，本审计保存本地验收依据。未执行真实 DSH UI、插件管理器整机安装/热重载、真实模型/网关、全部供应商 WS、缓存命中或 MySQL 外部服务器验证；模拟和宿主模块通过不冒充这些结论。
