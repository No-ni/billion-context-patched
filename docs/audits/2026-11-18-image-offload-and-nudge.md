# 用量提醒与宿主图片退役兜底审计

日期：2026-11-18。保留版本 `0.6.9`；本轮只构建临时候选并做本地离线验证，不提交、推送、发布、安装或修改真实用户配置。

## B18：用量提醒根因

根因成立。预检可能拿不到上游真实 `usage`，此时 `effectiveTokenCount` 会返回估算值。旧的中断回合处理只看 token 数是否超过中断锚点，没有检查来源；例如锚点为 100、预检估算为 150 时，会把估算误当成已送达模型的实际增长，移动提醒基准、消耗中断回合记录并清除已显示的提醒状态。估算并不能证明模型请求已经发生，因此这些状态变化是 bug。

修复在共享处理函数入口要求来源为真实 `usage`，四个调用点都传入来源。估算值仍可供窗口预检使用，但不能消费中断记录或改动提醒状态。回归位于 `scripts/check-views.mjs`：覆盖估算不变更状态、真实 usage 正常处理以及四个调用点均传来源。

## IMG-10/11：图片预算与宿主占位

宿主按请求图片数量退役旧图时，会把图像内容改成带完整 SHA-256 的文本占位。若插件此前已将相同图片改写成自己的引用说明，再把它转换成另一段宿主文本，会改变历史正文；即使图片本身已离开请求体，文本变化仍可能移动缓存前缀。

插件只在以下条件全部成立时恢复原说明：图片原始字节与本会话入站图片引用精确对应；该请求成功转发并完成图片回执；宿主占位含唯一、完整的 SHA-256，且该摘要只对应一个可用引用。恢复后的文本使用插件原本生成的精确说明，并按请求中是否提供原图工具选择对应版本。未知、重复、残缺或失去会话映射的占位保留宿主原文。扫描限定在四种协议的消息文本块；元数据和任意用户文本不改。会话映射最多保留 256 项。即使关闭图片折叠，已建立的可靠映射仍可用于这项文本兼容。

宿主图片预算默认每条请求最多 20 张，超限每次退役 10 张。图片卡可分别调整两个正整数；每次退役数不能大于总上限。设置只写入支持的 DeepSeek API Key 与 account 路由，用户未在插件里设值时保留原有宿主限额并只补缺项；显式插件值优先。宿主设置保存在其路由配置中，因此停用包装插件后仍生效。不支持的提供方、嵌套路由、自定义表达式和无效值均不写默认值。

## 构建迁移

首轮候选构建发现了另一处实际兼容 bug：本地 `0.6.9` 代理产物已包含此前的五个图像配置键，但 `scripts/patch-bili-build.mjs` 只识别尚未包含任何图像配置键的原始白名单，因此旧白名单命中数为零并中止构建。修复后代理补丁器接受原始、旧五键、新七键三种精确白名单；旧形式迁移到新形式，目标形式重复应用保持不变，未知或重复形式仍拒绝。native 宿主补丁器也覆盖旧五键迁移。实际未知配置键告警和去重未放宽。
