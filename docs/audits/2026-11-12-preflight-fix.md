后续用户授权的文档、推送与发布整理见[维护与发布核对](2026-11-12-maintenance-release.md)。下文保留本阶段当时的状态与构建证据。

## 来源与行为

- 起点：`main` / `9e770a6b48dbe26b24561b28875a858e0feacc0c`，0.6.6。没有合并或升级上游。
- billion-context 仍为 0.1.213 / `406193b202c13248241f25201e1c6bbda747c99b`；加速器仍为 2.3.0 / `e8c30af1f2b5cffa6749d032f0f296e17d4e26d0`。
- 新增 B22：共用预检入口遇到 live 快照降级、active 块存在且没有合格画面时，最多等待一秒让本会话保存完成，再调用原准备流程一次。重新渲染后重算预算；不依赖新增压缩范围才恢复，不修改引用或清空块，不绕过覆盖校验，不重复计请求数。
- 保存失败/超时不循环；断开不转发并清理恢复定时器和关闭监听。持续缺行等暂时状态补充可重试标记，确定性过大、图片/协议开销独自超限和终止性上游失败保留原保护；不因 seam/覆盖校验失败无条件重试。
- B19/B21：预检 HTTP 和四种已提交流错误统一中文、detail、retryable；413 保留，其余本地失败使用 502。摘要 429、解码繁忙不再额外产生本地 503/固定 retry-after；真实上游限流转发及原解码准入保护保留。
- `preflight.block.js` 可按哨兵更新，定点入口使用精确旧/新片段迁移；最终 dist 经 installer 的临时候选检查后生成。版本升至 0.6.7，规范、清单、使用入口与检查链同步。

这修复的是快照降级与预检之间缺少恢复机会的问题，没有重构存储事务，也没有证明原故障的某一个具体块如何失配。永久不满足完整性条件时仍可能拒绝请求，不能承诺所有冷加载或模型切换均可恢复。
