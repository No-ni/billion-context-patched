# 使用说明

## 插件商店安装

在 DSH 插件商店安装 **bili-context-patch**，随后启用。也可在「设置 → 插件」使用以下安装源：

```text
github:No-ni/billion-context-patched
```

包内自带所需运行文件，无需先安装 billion-context 或模型请求加速器。

首次启用自动停用原版 `billion-context`、`dsh-plugin-model-request-accelerator`，并迁移旧加速器配置。包装包已有值优先，渠道选择与禁用状态保留。原版仍出现在插件列表时，应显示关闭；两个设置页继续由本插件提供。

## 更新与重载

在插件管理器中更新 bili-context-patch。插件页安装的副本通过插件管理器更新；从本地仓库安装的副本也可使用「模型请求加速」页面底部的更新入口。

本版宿主修复需要重载插件或重启 DSH，图片代理修复需要重新启动 bili 代理。DSH 提示需要重启时按提示操作。仅重启代理不会重载包装包的宿主代码。

手动安装可使用下节命令重新部署并重启代理。已有配置会保留。

## 手动安装

已克隆本仓库且本机可运行 Node.js 时，在仓库根目录运行：

```sh
node scripts/install.mjs
node scripts/restart.mjs
```

安装脚本使用仓库自带的 vendor，并在替换正式构建前运行检查。更新仓库后重新运行安装即可，无需先卸载。其他 profile 的参数用法见[维护说明](MAINTENANCE.md)。

## 设置与默认值

bili 面板的「配置」页管理上下文压缩、缓存钥匙和图像设置。「模型请求加速」设置页管理渠道开关、请求压缩算法和耗时信息。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `promptCache.routing` | `enabled` | 支持路径上启用缓存钥匙；显式 enabled / auto / disabled 保留 |
| `compress.nudgeGrowthTokens` | `80000` | 两次折叠之间的压缩增长阈值；显式值优先 |
| `imageRetention` | `true` | 成功发送后的图片折叠与首次按需压缩 |
| `imageRetentionKeepLastUser` | `true` | 当前回合用户上传的图保留，不提前折叠 |
| `imageRetentionMaxDim` | `1200` | 首次压缩的长边上限，最小 128 |
| `imagePrompt` | `true` | 恒定的图像使用约定 |

图像卡先修改页面草稿，点击保存后对下一条请求生效。「恢复默认」删除四个图像配置键，其他配置保留。同名环境变量仍然优先；页面展示文件中的配置。

### 指定中转渠道

主机名为 `www.didudidu.asia` 或 `154.219.111.56` 的渠道仅补缺失的 `enabled: true` 与 `encoding: auto`。按主机匹配，重命名渠道不影响；服务或渠道稍后出现时也会补齐。

`auto` 在支持的路径上优先 br，可在不支持或拒绝 br 时回退 gzip；`gzip` 只尝试 gzip。手动关闭、显式算法、null、配置表达式及显式全局 gzip 不会被默认值覆盖。其他主机需在加速器设置页自行开启。

### 图片折叠与压缩

图片只有在请求成功发送后才记为看过；失败或超时的请求不会提前折叠。折叠后的文字包含尺寸、引用号和取回提示，原图可通过 `acp_read_original_image` 按引用取回。

首次压缩借用已有编码器：macOS 的 sips、Windows PowerShell 的 System.Drawing，其他平台的 ImageMagick。没有可用编码器时保留原图；压缩产物达不到收益条件时也保留原图。修改长边上限后，下一条请求按新值重新计算。

### 快照渲染与诊断

插件道的服务端快照渲染遵守本地标记及 snapshot live/shadow 开关，安装本包不自动复制机器上的标记或灰度配置。需要调整时按[行为规范 B2](SPEC.md#b2插件道快照渲染)和[维护说明](MAINTENANCE.md)核对当前环境。

请求正文诊断落盘默认关闭，仅在诊断标记存在时开启。历史缓存命中率不代表所有渠道的预期效果。

## 常见问题

### 更新后原版卡片还在

插件管理器保留原版的安装所有权，卡片可能仍显示；首次启用后原版应关闭，由 bili-context-patch 提供功能。确认本包已启用且当前加载的是 0.6.5，按提示重载或重启。

### 指定渠道没有变成开启

确认主机名精确匹配上述两个地址。如果已有手动关闭或其他显式设置，本包会保留它们。算法中的「自动」就是优先 br；实际传输可查看加速器的请求信息。

### 日志出现条目未找到

某些 DSH 版本或未装过原版的 profile 没有被组合层引用的原版条目，可能出现 skipped / not-found 警告。重复路由、重复账本或 startup failed 属于另一类错误；反馈时附版本、加载方式与相关日志。

### 功能没有立即变化

图像设置保存后从下一条请求生效。宿主代码需要重载插件或重启 DSH；代理代码需要重启 bili 代理。代码更新与配置保存的生效时机分别见上文。

## 卸载

在「设置 → 插件」卸载 bili-context-patch，也可运行：

```sh
dsh plugin --profile desktop remove bili-context-patch
```

本包停用后，其子插件随之停用。此前已停用的原版插件如需继续使用，可在插件页重新启用。
